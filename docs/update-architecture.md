# 软件更新

ZcVersionBox 的软件更新由主窗口级 `UpdateService` 统一管理。应用启动后延迟 5 秒执行一次后台检查，不阻塞窗口显示或备份监控；发现新版本时通过应用内通知和“关于”入口的小红点提醒，进入关于页后红点清除，用户可查看 Markdown 更新说明。关于页应用信息右侧的“检查更新”按钮仍支持手动触发检查。应用不执行静默安装，也不会替换正在运行的程序。

## 检查流程

1. 应用启动 5 秒后通过 HTTPS 请求 `https://api.github.com/repos/Zao-chen/ZcVersionBox/releases/latest`；如果用户在延迟期间已经手动检查，则以该次手动检查作为本次启动检查，避免重复请求。
2. 只接受稳定 Release，并严格校验 `vMAJOR.MINOR.PATCH` 版本号。
3. 使用数值比较主、次、补丁版本，不按字符串排序。
4. 后台检查只通过通知提示新版本，不弹出模态窗口；用户在关于页查看时，在固定尺寸的对话框中显示当前版本、最新版本和 Markdown 发布说明。说明区域可滚动，避免长文本撑大窗口，并提供打开 GitHub 发布页的入口。

网络请求有 12 秒超时。HTTP 错误、TLS 错误、JSON 格式错误和版本号错误都会结束本次检查，不打断主窗口和备份监控；手动检查会显示可重试的失败提示，后台检查保持安静。

## 下载流程

当前平台安装包按发布工作流的固定命名匹配：

| 平台 | 安装包后缀 |
| --- | --- |
| Windows | `-setup.exe` |
| macOS | `.dmg` |
| Linux | `-linux-amd64.deb` |

下载先写入 `QSaveFile` 临时文件，完成且网络无错误后再原子提交到系统下载目录。如果目标文件已存在，则自动使用带序号的文件名，不覆盖用户已有安装包。下载支持进度显示和取消，失败或取消会清理临时文件。

应用不自行替换正在运行的可执行文件。下载完成后由用户打开安装包；没有匹配安装包的平台仍可打开 GitHub 发布页手动选择资源。
