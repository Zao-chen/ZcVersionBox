# 多人协作与自动同步

每个备份对象都有独立的“多人协作”页。一次同步会保存当前源位置已经落盘的修改，获取全部云端方案和里程碑，整理当前文件，再发送全部本地方案的已保存历史及里程碑。只有全部阶段完成才显示“已同步”。

## 连接与加入

1. 在 Git 仓库平台创建共享仓库，给协作者分配访问权限。沿用电脑现有的 Git 地址与认证方式；仓库需支持 atomic push。空仓库可直接作为首次发布目标。
2. 在对象的“多人协作”页填写地址，点击“连接”。修改已连接的地址后，点击“保存并连接”才生效。
3. 点击“立即同步”完成首次发布，再点击“复制协作地址”。协作者在自己的应用中选择“添加备份 → 从云端导入”，填写该地址，选择内容和本机存放位置。

连接及导入后默认开启自动同步。关闭“自动同步”会保留连接和“立即同步”；“断开连接”移除当前云端连接，本地文件与历史仍保留。断开不删除共享仓库中的内容。

## 日常使用

- 本地版本、方案或里程碑实际变化后，等待 3 秒合并连续事件；每 30 秒检查协作者更新。启动应用或开启自动同步后会安排首次检查。
- 当前方案无冲突的新增、修改和删除自动应用；没有变化时不创建空版本，不重复推送。同步保存不等待 AI 生成说明。
- 其他本地方案只落后云端时，安全推进其版本，不切换当前工作文件。云端独有方案保留在方案列表中，由用户选择是否加入使用。
- 所有本地方案沿用已有的云端关联。删除本地方案不会自动删除云端方案；普通同步不会强制覆盖分叉历史。
- 应用内编辑器有未保存修改时暂缓同步；保存或放弃后继续。断网不影响正常本地备份；网络失败从 15 秒开始退避，最长 5 分钟，手动同步可立即重试。认证和配置错误需修正后重试。

页面显示实际阶段、最近成功时间和全部方案的处理结果。“查看同步详情”可展开具体问题。后台成功保持安静，不跳转页面；失败或待处理事项去重提醒，“多人协作”标签显示待处理提示。

## 处理差异

双方修改同一处内容时，主操作变为“处理差异”。逐处选择本地或云端内容，查看最终预览，再确认应用；成功后自动继续全量同步。该对象等待处理期间释放服务队列，其他对象继续工作。

如果分叉发生在其他本地方案，主操作为“切换方案并处理”，并显示方案名。确认切换后进入该方案的同步；当前修改先按既有流程保存。其他方案待处理本身不会暂停本地备份或禁止切换。

“稍后处理”保留会话和已选内容，退出、重启后仍可继续。只有实际进入冲突会话时，才沿用暂停当前对象自动备份的规则。取消云端会话使用“取消本次并关闭自动同步”，避免取消后立即再次触发。普通本地方案合并仍使用原流程，不自动续接云端同步。

同名里程碑指向不同版本时，在历史版本页处理标记，处理完后自动续接。若版本已发送而里程碑失败，页面显示“版本已同步，里程碑尚未完成”；后续重试补齐，不把这轮显示为全部成功。

处理会话固定当时的输入。源文件、仓库代次、工作方案或会话修订发生变化时，旧结果不能直接应用；重新分析会清除旧选择。发送期间云端再变化，每轮最多自动重新协调一次，持续变化转为稍后重试。源写入无法确认完成时保留恢复材料并进入“需要检查”，不会继续自动写入。

## 双端验收

使用两个独立应用实例的测试对象，分别称为 A、B，连接同一个临时仓库；不要用重要工作目录试验删除和冲突。

1. **首次共享**：A 添加包含多个文件的文件夹，创建第二个方案及里程碑，连接空仓库并同步。B 从该地址导入；核对内容、所有云端方案和里程碑。已有本地方案应默认自动同步。
2. **自动接收**：A 保存一个修改、新增一个文件、删除另一个文件。等待本地保存及 3 秒合并窗口，在 B 的下一次 30 秒检查后核对三种变化。连续保存应合并请求；再次手动同步不增加无意义版本。
3. **同时编辑**：临时关闭两端自动同步，分别修改同一文本的不同行。A、B 依次手动同步，应自动合并并保留双方内容。再修改同一行，B 同步后应要求选择；稍后处理、重启、继续选择、预览并应用，最终两端再次同步后相同。
4. **其他方案**：A 更新第二个方案，B 留在主方案同步，第二方案应安全推进而当前文件不切换。再让两端第二方案分叉；B 在主方案同步时应提示具体方案，并停止整批发送。点击“切换方案并处理”，处理后所有本地方案恢复同步。
5. **云端独有与关联**：A 新建方案，B 同步后只在云端列表看到它；使用“加入并使用”才创建本地方案。本地改名后同步应沿用原云端名称。删除本地方案后，云端方案仍在。
6. **未完成工作**：制造同名里程碑冲突，处理后应自动续接；断网保存文件，本地历史仍可创建。恢复连接后重试补齐。关闭自动同步后继续保存，云端不自动改变，手动同步仍可用。
7. **编辑与生命周期**：B 在应用内编辑但不保存，A 发送更新，B 应显示等待编辑；保存或放弃后继续。冲突期间编辑源文件，旧确认应拒绝并提供重新分析。取消云端会话应关闭自动同步。让另一测试对象同步，确认不受待处理对象影响。
8. **页面**：切换对象、前后退和设置往返，连接地址与反馈必须属于正确对象。检查浅深色及 1080×740、760×520 窗口，窄窗口使用纵向滚动，地址编辑未保存前不改变连接。

## 本次开发验证

在 macOS arm64 / Qt 6.8.3 上复用 `build` 增量编译。使用隔离配置、临时源目录和本地 bare 仓库的 `zc_backup_tests`、`zc_tests`，按函数运行新增及直接受影响的同步、调度、合并保护和页面测试。没有启动正常应用进行自动回归，也没有运行全量 CTest。函数清单和结果见 [回归验证](ui-regression.md#多人协作与自动同步2026-10-15)。

页面截图位于 `build/collaboration-screenshots/`，已检查浅深色及两种尺寸。真实托管仓库认证、跨机器网络和 Windows/Linux 原生布局仍需按以上双端步骤验收。
