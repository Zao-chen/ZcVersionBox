# 方案：项目的一套共享版本线

一个方案是一条独立的版本线。项目只有一套方案，连接共享仓库后各设备自动同步名称、版本和删除操作。内容、父提交和引用仍保存在原生 Git 仓库中；应用用固定身份记录方案的改名与删除，不保存每方案源文件副本。

## 使用

| 操作 | 入口与结果 |
| --- | --- |
| 列表 | 只分“正在使用 / 其他方案”，每行显示名称、最新说明和更新时间，不显示本地/远程类型或“加入”入口。单击或回车查看历史，不切换工作方案；行内和右键菜单提供操作。 |
| 新建 | 顶部“新建方案”从当前版本开始；行菜单“从此方案新建”和历史版本行“新建方案”可以指定起点。创建本身不提交内容，可选择立即使用；连接后自动共享。 |
| 切换 | 顶部“方案：名称”菜单或方案行“切换到此方案”。确认后先把修改保存到原方案，再更新源位置；没有修改不创建空版本。切换只影响本机，不改变其他协作者正在使用的方案。 |
| 浏览与比较 | 历史范围、关系图和前进后退只改变浏览对象。关系图每个方案只显示一个标签，不把尚未同步的副本标成另一个“云端方案”。比较固定两个完整提交编号。 |
| 合并 | 来源行的“合并到正在使用的方案”。来源保留；内容冲突逐处选择，预览后应用，可以稍后继续或取消。 |
| 改名 | 修改同一个方案的名称，同步后所有设备使用新名称，不留下旧名称副本。尚未联网时先记录改名，重启后继续发送。 |
| 删除 | 确认“删除共享方案”，同步移除共享仓库及其他设备上的该方案。当前方案须先切换；有尚未合入当前方案的版本时再次确认。云端副本不再被视为删除后的独立保留方案。 |
| 同步 | “多人协作 → 立即同步”保存已落盘的修改，获取全部方案与里程碑，协调目录和内容，再原子发送方案。当前方案无冲突更新自动应用；非当前方案在隔离仓库自动合并，不切换源文件。 |

方案页只负责方案操作；地址、自动同步开关和“立即同步”统一位于“多人协作”。连接后默认开启自动同步：本地变化后等待 3 秒，每 30 秒检查更新。断网继续备份，恢复连接后补齐；关闭自动同步后仍可手动同步。

## 离线与并发保护

- 已删除方案的身份持续保留。旧设备重新联网时移除旧名称，不会因“缺少分支”而重新上传它。
- 如果被删除的方案正在本机使用，或包含不在删除版本内的工作，保留为 `原名-保留-短编号`，作为新方案共享。源内容不被替换，并提示新名称。
- 确认删除后，协作者若新增了未包含在确认版本内的提交，或修改了方案名称，会撤销本次删除、重新接收方案，并提示查看后再次确认。
- 两端同时改名时采用共享仓库已接受的名称，并提示本机用户；版本内容继续协调。不同身份发生名称碰撞时给另一份工作加“保留”后缀，不覆盖方案。
- 可以通过应用新建一个与已删除方案同名的新方案；它使用新身份，不与旧设备持有的已删除方案混淆。
- 非当前方案分叉但没有内容冲突时自动合并；只有真正的内容冲突才要求切换到对应方案处理。

## 名称、文件和历史

中文名称可直接使用。Git 不允许空格、`..`、`~`、`^`、`:`、`?`、`*`、`[`、反斜线等形式；名称不能以横线开头或以 `.lock` 结尾，完整限制由 `git check-ref-format` 检查。

切换有修改的方案时，连续执行 **保存到原方案 → Git switch → 更新源位置**。不等待 AI 生成说明，不创建空提交，其他应用任务不能插入这段操作。

被忽略的文件仍是当前工作区的文件，不随方案保存一套副本。潜在覆盖会阻止切换并返回具体原因；源位置的 `.git` 元数据会保留。符号链接、子模块等既有限制仍然适用。

合并能快进时直接快进；分叉时产生真实双亲合并提交；已包含时不新增提交。来源方案保留。无共同历史时停止，二进制和整文件冲突沿用现有选择界面。

里程碑仍是仓库共享的 Git tag。修改最新说明使用 amend，只更新当前分支，其他分支仍引用原提交；里程碑版本的说明不可改。已上传版本改说明后可能遇到非快进拒绝。

删除从方案列表移除引用。待同步删除的版本由内部 `refs/zcversionbox/deleted/<身份>` 保留，成功发送的删除版本也作为目录提交的父提交保留。应用没有回收站界面；需要恢复时可从保留引用新建原生 Git 分支。

## 实现边界

- `BackupSchemes`（`utils/backup_schemes.*`）协调固定 UUID、名称、版本和删除状态。共享目录是 `refs/zcversionbox/schemes` 指向的提交，其中包含 `schemes.json`，不出现在方案列表和普通版本历史中。
- 记录文件的 `schemes` 保存本机意图，`schemeBase` 保存接收基线，`schemeEndpoint` 和 `schemeRevision` 绑定端点及目录历史。旧记录按现有分支和 upstream 自动建立身份。原有不同名关联以本机名称作为待同步改名；多端不一致时采用先被共享仓库接受的名称。更换端点不向新仓库重放旧仓库的删除。
- 目录和分支在一次 atomic push 中发送，每个目标及目录均绑定读取时的预期 OID。普通内容更新先检查快进关系；只有已确认的删除和改名会移除旧引用。目录被移除或改写时停止同步，避免丢失删除记录。
- `BranchInfo` 从 Git 引用读取；`BranchContext` 包含对象 ID、完整工作分支引用、HEAD、仓库代次和分支上下文版本。
- 现行格式旧记录经过已有仓库/源基线检查后补齐分支字段，不改写版本历史。更早的旧存储格式仍沿用原有导入方式。
- 写请求经过 `BackupService` 串行队列和 `QLockFile`。队列、确认结果、合并会话和监控快照绑定分支身份；相同提交的不同分支也使旧上下文失效。
- `PreparedBranchSwitch` 固定目标 OID、当前上下文和源指纹。确认后重查目标与源，在隔离候选仓库预演 Git 切换；候选仓库不是按分支持久保存的缓存。
- 源替换复用 `BackupReplacement`，先持久记录操作和恢复路径，成功后更新分支、提交、监控基线。无法确认现场安全时保留恢复材料并暂停，不自动强制 reset。重启发现未完成标记也保持暂停。
- 合并复用持久候选仓库与冲突页，候选捕获沿用仓库本地忽略/规范化配置，最终树和父提交写入真实仓库。本地合并使用 Git 默认合并策略，重命名冲突按实际 index stages 读取两侧。取消只清理本次处理状态，源文件保持原样；重新分析显式更新输入。
- 上传/重建基线按远程端点和目标分支隔离。端点包含远程名、全部读取/推送地址。全量上传固定每个本地方案的 OID，正常分支只允许快进；已确认重建的分支仍使用预期 OID 的 lease。方案上传成功而里程碑失败时单独报告，并可重试。
- 重建会替换整个仓库，存在其他本地、遗留归档或其他已知云端分支时禁止执行。检查所有配置远程的读取和推送地址，无法确认范围时停止；候选完成后再次校验。
- 默认历史可指定分支，关系图按真实 `%P` 父提交绘制并标注分支/tag。查询分批执行，关系图每批 200 条，后续批次固定首次查询的提交集合。

共享仓库必须支持 atomic push、自定义 `refs/zcversionbox/schemes` 引用，并使用一个读写一致的地址。服务器保护的默认分支或受保护分支可能拒绝改名/删除，需要仓库管理员先调整保护或默认分支。失败会保留本机意图，不显示“已同步”。

启用全局改名和删除前升级所有协作者。旧版本及外部 Git 工具不认识方案身份；若重新上传了已删除的名称，新版本停止同步并提示先将需要保留的工作改为新名称。日常内容提交仍可使用原生 Git；方案改名、删除和同名重建应通过新版应用完成。

不提供 rebase、cherry-pick、stash 管理或多工作目录界面。

## 验收步骤

使用临时项目和临时裸远程仓库。

1. 在“方案”页签点击“新建方案”创建中文方案，取消“创建后立即使用”。用 `git for-each-ref refs/heads` 检查两个引用，提交数应不增加；列表只显示“正在使用 / 其他方案”，没有本地/远程类型。
2. 修改源文件，切换到新方案。确认框应说明先保存；原方案新增提交，新方案保持创建时版本。无变化切换不增加提交。
3. 在忽略目录放文件并来回切换，内容应保留；让目标方案追踪同名文件，应阻止覆盖并说明路径。
4. 用历史页“只看：名称”、关系图和前进后退浏览，顶部当前方案及源内容保持。方案列表单击进入该方案的历史且不切换。核对浅深色、760/1080 像素窗口、Tab 焦点、列表方向键与确认按钮。
5. 两方案分别修改同一文件，比较后合并到当前方案。处理冲突、预览、应用；用 `git show -s --format=%P HEAD` 核对父提交，用 `git diff <旧OID> <新OID>` 核对内容。
6. 验证快进、已包含、取消、重启继续及外部修改后拒绝应用。候选处理期间源文件不应被提前替换。
7. A 连接临时共享仓库，B 从该仓库导入。A 新建方案后同步，B 自动显示该方案，直接切换时只有原有切换确认。
8. A 改名，B 同步后只保留新名称；B 正在使用该方案时名称更新，但工作文件不被切到另一方案。
9. A 删除非当前方案，B 离线后重启再同步；旧名称不能复活。若 B 有未同步工作或正在使用被删方案，应出现独立的“保留”方案，内容不丢失。
10. A 确认删除后，B 先发送新提交；A 同步应取消该次删除并提示。两端同一身份改成不同名称时采用先发送的名称，内容不被覆盖。
11. 两端在非当前方案修改不同文件，同步应自动合并且当前源内容不变；修改同一处内容时才要求切换处理。模拟断网、发送拒绝及重启，恢复后补齐。
