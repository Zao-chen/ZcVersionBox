# 方案：Git 原生分支

方案名称就是 Git 分支名称。版本、父提交、引用和 upstream 都保存在普通 Git 仓库中；应用负责确认、源文件同步和结果提示。不建立方案归档、每方案缓存副本或自定义文件排除规则。

## 使用

| 操作 | 入口与结果 |
| --- | --- |
| 列表 | 对象页签“方案”按“正在使用 / 其他方案 / 云端方案（尚未加入）”分区列出，每行显示名称、最新说明和更新时间，已共享的方案带云朵图标。已关联本地方案的云端分支不单独列出。列表没有选中状态，操作都在行内：悬停显示“切换到此方案”（云端方案常驻“加入…”），右侧 ⋯ 或右键打开操作菜单。单击或回车查看该方案的历史，不切换方案。 |
| 新建 | 方案页顶部的“新建方案”从当前最新版本开始；方案行菜单的“从此方案新建”从该方案最新版本开始；历史版本行的“新建方案”按钮或右键菜单中的“从此版本新建方案”以选中版本为起点。可选创建后立即使用，创建本身不提交内容。 |
| 切换 | 顶部“方案：<名称>”菜单（正在使用的方案前打勾，其余方案点击即切换；不含新建），或方案行的“切换到此方案”。确认框说明从哪个方案切到哪个、源位置文件会变成目标方案内容以及是否先保存，变化文件列表默认折叠；取消不改变内容。不可切换时菜单仍可打开并说明原因。 |
| 浏览 | 历史页“显示全部方案 / 只看当前方案 / 只看：名称”、关系图和前进后退只改变浏览对象，不切换当前工作方案。点击关系图中的方案标签或连线，历史页筛选为该方案；筛选后显示该方案的完整历史。同一版本上同名的本地与云端副本只显示一个标签。 |
| 比较 | 方案行菜单“与其他方案比较”，或关系图选择两个版本。比较固定两个完整提交编号。 |
| 合并 | 在来源方案的行菜单选择“合并到正在使用的方案”。逐处处理冲突，预览后应用；可稍后继续或取消。 |
| 改名 | 行菜单“重命名”。本地名称改变，Git upstream 保留；云端名称不自动修改。 |
| 删除本地 | 行菜单“删除”。先确认一次并执行 Git 的已合并检查（有 upstream 时按 upstream 检查）；方案含独有版本时再次确认“仍然删除”才强制删除。当前方案须先切换。 |
| 同步 | “多人协作 → 立即同步”保存当前已落盘的修改，获取全部方案与里程碑，自动应用当前方案无冲突的更新，再整批发送。非当前本地方案仅在落后时安全快进；分叉时提示切换处理。 |
| 使用云端 | 创建本地跟踪分支，再走确认切换流程。同名本地分支已存在时需换名或直接选择已有分支。 |
| 自动同步 | 连接后默认开启，本地版本、方案或里程碑变化后等待 3 秒，每 30 秒检查云端。全部本地方案经检查后通过 atomic push 发送；首次共享建立同名 upstream，已有 upstream 保留实际目标。 |

方案页只提供浏览、使用及本地管理，云端地址、自动同步开关与同步入口统一在“多人协作”。删除本地方案不会在全量上传时删除云端方案；云端已有但本地未采用的方案也会保留。不同本地方案指向同一个云端目标、或关联了不同远程时会明确停止上传，不悄悄改写对应关系。Git 服务器须支持 atomic push。

中文名称可直接使用。Git 不允许空格、`..`、`~`、`^`、`:`、`?`、`*`、`[`、反斜线等形式；名称不能以横线开头或以 `.lock` 结尾，完整限制由 `git check-ref-format` 检查。

切换有修改的方案时，连续执行 **保存到原方案 → Git switch → 更新源位置**。不等待 AI 生成说明，不创建空提交，其他应用任务不能插入这段操作。

被忽略的文件仍是当前工作区的文件，不随方案保存一套副本。潜在覆盖会阻止切换并返回具体原因；源位置的 `.git` 元数据会保留。符号链接、子模块等既有限制仍然适用。

合并能快进时直接快进；分叉时产生真实双亲合并提交；已包含时不新增提交。来源方案保留。无共同历史时停止，二进制和整文件冲突沿用现有选择界面。

里程碑仍是仓库共享的 Git tag。修改最新说明使用 amend，只更新当前分支，其他分支仍引用原提交；里程碑版本的说明不可改。已上传版本改说明后可能遇到非快进拒绝。

删除没有应用自建回收站。失去分支引用的提交是否仍能找到，取决于其他 Git 引用、reflog 和对象回收，应用不承诺永久保留。

## 实现边界

- `BranchInfo` 从 Git 引用读取；`BranchContext` 包含对象 ID、完整工作分支引用、HEAD、仓库代次和分支上下文版本。
- 现行格式旧记录经过已有仓库/源基线检查后补齐分支字段，不改名或改写历史。更早的旧存储格式仍沿用原有导入方式。
- 写请求经过 `BackupService` 串行队列和 `QLockFile`。队列、确认结果、合并会话和监控快照绑定分支身份；相同提交的不同分支也使旧上下文失效。
- `PreparedBranchSwitch` 固定目标 OID、当前上下文和源指纹。确认后重查目标与源，在隔离候选仓库预演 Git 切换；候选仓库不是按分支持久保存的缓存。
- 源替换复用 `BackupReplacement`，先持久记录操作和恢复路径，成功后更新分支、提交、监控基线。无法确认现场安全时保留恢复材料并暂停，不自动强制 reset。重启发现未完成标记也保持暂停。
- 合并复用持久候选仓库与冲突页，候选捕获沿用仓库本地忽略/规范化配置，最终树和父提交写入真实仓库。本地合并使用 Git 默认合并策略，重命名冲突按实际 index stages 读取两侧。取消只清理本次处理状态，源文件保持原样；重新分析显式更新输入。
- 上传/重建基线按远程端点和目标分支隔离。端点包含远程名、全部读取/推送地址。全量上传固定每个本地方案的 OID，正常分支只允许快进；已确认重建的分支仍使用预期 OID 的 lease。方案上传成功而里程碑失败时单独报告，并可重试。
- 重建会替换整个仓库，存在其他本地、遗留归档或其他已知云端分支时禁止执行。检查所有配置远程的读取和推送地址，无法确认范围时停止；候选完成后再次校验。
- 默认历史可指定分支，关系图按真实 `%P` 父提交绘制并标注分支/tag。查询分批执行，关系图每批 200 条，后续批次固定首次查询的提交集合。

本轮不提供 rebase、cherry-pick、stash 管理或多工作目录界面。

## 验收步骤

使用临时项目和临时裸远程仓库。

1. 在“方案”页签点击“新建方案”创建中文方案，取消“创建后立即使用”。用 `git for-each-ref refs/heads` 检查两个引用，提交数应不增加；列表应显示两个“仅本机”方案。
2. 修改源文件，切换到新方案。确认框应说明先保存；原方案新增提交，新方案保持创建时版本。无变化切换不增加提交。
3. 在忽略目录放文件并来回切换，内容应保留；让目标方案追踪同名文件，应阻止覆盖并说明路径。
4. 用历史页“只看：名称”、关系图和前进后退浏览，顶部当前方案及源内容保持。方案列表单击进入该方案的历史且不切换。核对浅深色、760/1080 像素窗口、Tab 焦点、列表方向键与确认按钮。
5. 两方案分别修改同一文件，比较后合并到当前方案。处理冲突、预览、应用；用 `git show -s --format=%P HEAD` 核对父提交，用 `git diff <旧OID> <新OID>` 核对内容。
6. 验证快进、已包含、取消、重启继续及外部修改后拒绝应用。候选处理期间源文件不应被提前替换。
7. 在“多人协作”连接临时远程，创建多个本地方案后点击“立即同步”，非当前方案和里程碑都应共享。远端新建其他方案后再次同步，云端独有方案可浏览而不自动采用；当前方案无冲突的更新自动应用，其他本地方案只快进引用，不切换源文件。
8. 本地改名，确认同步仍关联旧云端名称。删除已合并的本地方案只确认一次，删除含独有版本的方案会再次确认；同步后云端方案应保留。连接后同名的本地与云端方案在列表、范围下拉框和关系图标签中只出现一次。让非当前方案与云端分叉，本轮应停止整批发送，显示具体方案名；通过“切换方案并处理”完成后自动继续发送全部方案。
